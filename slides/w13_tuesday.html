What is Unsupervised Learning?

Supervised vs. Unsupervised Learning

Everything we’ve done so far has been supervised learning:

Supervised Learning

  • You have a target variable (labels)
  • Goal: Predict the outcome
  • Examples:
    • Predict house prices
    • Classify loan defaults
    • Diagnose diseases
  • Success metric: Accuracy, RMSE, etc.

Unsupervised Learning

  • No target variable (no labels)
  • Goal: Discover hidden patterns
  • Examples:
    • Find customer segments
    • Group similar documents
    • Reduce feature complexity
  • Success metric: Interpretability, business value

Main Takeaway: Unsupervised learning is fundamentally different from everything we’ve done so far—we discover patterns instead of predicting outcomes.

Key Teaching Points:

  • The Big Shift: Up until now, every model had a target variable (y). Now there’s NO target—just features (X)
  • Success metrics change: We can’t measure accuracy or RMSE anymore. Success = interpretability + business value
  • Real-world context: Often you collect data but don’t know what patterns exist yet. Unsupervised learning helps you explore and understand your data
  • Examples to mention:
    • Supervised: “Predict which customers will churn” (you need historical churn labels)
    • Unsupervised: “Find natural customer segments” (no predetermined groups needed)
  • Common student question: “How do we know if we’re right?” Answer: “We validate with domain experts and measure business impact, not statistical accuracy”

Two Main Types of Unsupervised Learning

Key Distinction

Clustering is focused on finding groupings amongst the rows (observations) — grouping similar customers, products, or data points together.

Dimension Reduction is focused on finding groupings amongst the columns (features) — combining correlated features into composite components.

Main Takeaway: There are two fundamentally different types of unsupervised learning—clustering works on ROWS, dimension reduction works on COLUMNS.

Critical Distinction (emphasize heavily):

  • Clustering: “Which customers are similar to each other?” → Groups rows
  • Dimension Reduction: “Which features capture similar information?” → Combines columns
  • This is a common point of confusion—make sure students understand the difference!

Today’s Focus:

  • K-Means clustering: Most widely used clustering algorithm in business
  • PCA: Most common dimension reduction technique
  • These are the “workhorses”—students will see them constantly in industry

Diagram Interpretation:

  • Point out the other methods listed (Hierarchical, DBSCAN, t-SNE, Autoencoders) to show there’s a whole ecosystem
  • But K-Means and PCA are the foundations that everyone should know
  • The other methods build on or extend these core ideas

Clustering: Groups ROWS (observations)

Key Takeaway

Clustering finds groupings amongst the ROWS — it identifies which observations (customers, products, patients) are similar to each other and groups them together.

“These customers behave similarly”

Main Takeaway: Clustering operates on ROWS—it finds groups of similar observations.

Visual Walkthrough:

  • Point to the matrix visualization showing 8 rows (customers) and 18 features
  • Notice how entire ROWS are color-coded together (Premium = red, Regular = teal, Inactive = blue)
  • Each row represents one customer across all their features
  • The algorithm looked across all 18 features to determine “these 3 customers are similar”

Emphasize:

  • The number of rows stays the same (8 customers → still 8 customers)
  • We’re just adding a new piece of information: cluster membership
  • Each customer now has a label: Premium, Regular, or Inactive
  • This labeling happened automatically based on patterns in the features

Real-World Application: “If this were a real retailer, you might find that Premium customers all have high spending, frequent visits, and low discount usage. The algorithm discovered this pattern without being told what makes a customer ‘premium.’”

Dimension Reduction: Combines COLUMNS (features)

Key Takeaway

Dimension Reduction finds groupings amongst the COLUMNS — it identifies which features are correlated and combines them into composite components.

“These features capture similar information”

Main Takeaway: Dimension reduction operates on COLUMNS—it combines correlated features into composite components.

Visual Walkthrough:

  • Original matrix: 8 rows × 5 features (Sq Ft, Bedrooms, Bathrooms, Location Score, School Rating)
  • Notice the color coding: Red features (Sq Ft, Bedrooms, Bathrooms) → PC1 “Overall Size”
  • Teal features (Location Score, School Rating) → PC2 “Location Quality”
  • After PCA: 8 rows × 2 components (60% fewer features!)

Key Contrast with Clustering:

  • Clustering changed: ROWS (which customers are grouped together)
  • PCA changes: COLUMNS (which features are combined)
  • Clustering output: Same features + cluster label
  • PCA output: New features (principal components)

House Example Explanation: “Sq Ft, bedrooms, and bathrooms are all highly correlated—big houses have more of everything. Instead of storing all three, we can create ONE composite measure called ‘Overall Size’ (PC1) that captures most of that information. Similarly, location score and school rating both relate to neighborhood quality, so we combine them into PC2.”

Emphasize: We went from 5 features to 2 components while keeping the same 8 houses!

Clustering: Finding Natural Groups

What is Clustering?

Clustering automatically groups similar observations together without being told what the groups should be.

Real-world applications:

  • Marketing: Segment customers by behavior
  • Retail: Group products by purchase patterns
  • Healthcare: Identify patient subtypes
  • Fraud detection: Find unusual transaction patterns
  • Document analysis: Organize similar articles
  • Image compression: Group similar pixels

Emphasize that clustering finds groups that exist naturally in the data—we don’t tell it what the groups should look like ahead of time.

The Big Question: How Many Clusters (K)?

Problem: K-Means requires you to specify the number of clusters upfront. But how do you know what K should be?

Elbow Method

  1. Try different values of K (e.g., 2, 3, 4, 5, 6…)
  2. Measure “inertia” (within-cluster sum of squares)
  3. Plot inertia vs. K
  4. Look for the “elbow” where adding more clusters doesn’t help much

Lower inertia = tighter clusters = better fit

Silhouette Score

  • Measures how similar each point is to its own cluster vs. other clusters
  • Ranges from -1 (wrong cluster) to +1 (perfect cluster)
  • Higher is better
  • Typical good score: 0.5-0.7

Silhouette score balances cluster tightness with separation

Main Takeaway: K-Means requires you to choose K upfront, but we have two complementary methods to help make this decision.

Elbow Method - Deep Explanation:

  • What is inertia? Sum of squared distances from each point to its cluster center
  • Why does it decrease? More clusters = points closer to their centers on average
  • The “elbow”: The point where adding more clusters gives diminishing returns
  • How to spot it: Look for the “bend” where the curve starts flattening out
  • Limitation: Sometimes there’s no clear elbow (we’ll see this with real data!)

Silhouette Score - Deep Explanation:

  • What it measures: For each point, how similar is it to its own cluster vs. the nearest other cluster?
  • Score = +1: Perfect! Point is very close to its cluster center and far from others
  • Score = 0: Point is on the boundary between two clusters (could go either way)
  • Score = -1: Wrong cluster! Point is closer to a different cluster
  • Overall score: Average across all points
  • Good scores: 0.5-0.7 for well-separated clusters; 0.2-0.4 is acceptable for messy real-world data

Key Teaching Point:

“These are GUIDES, not rules. The best K depends on:

  1. Statistical fit (elbow & silhouette)
  2. Business needs (can marketing handle 5 segments or only 3?)
  3. Interpretability (can you clearly describe each cluster?)
  4. Actionability (can you do something different for each segment?)”

Common Question: “Which metric should I trust more?” → Use BOTH together. If they agree, great! If they disagree, try a few values of K and see which produces the most interpretable segments.

Demo: Finding the Right K

from sklearn.metrics import silhouette_score

# Try K from 2 to 8
K_range = range(2, 9)
inertias = []
silhouettes = []

for k in K_range:
    km = KMeans(n_clusters=k, random_state=42, n_init=10)
    km.fit(customers_scaled)
    inertias.append(km.inertia_)
    silhouettes.append(silhouette_score(customers_scaled, km.labels_))

# Plot both metrics
fig, (ax1, ax2) = plt.subplots(2, 1, figsize=(6, 6))

# Elbow plot
ax1.plot(K_range, inertias, 'bo-', linewidth=2, markersize=8)
ax1.set_xlabel('Number of Clusters (K)', fontweight='bold')
ax1.set_ylabel('Inertia (Within-cluster SS)', fontweight='bold')
ax1.set_title('Elbow Method', fontweight='bold')
ax1.grid(True, alpha=0.3)
ax1.axvline(x=3, color='red', linestyle='--', alpha=0.5, label='Elbow at K=3')
ax1.legend()

# Silhouette plot
ax2.plot(K_range, silhouettes, 'ro-', linewidth=2, markersize=8)
ax2.set_xlabel('Number of Clusters (K)', fontweight='bold')
ax2.set_ylabel('Silhouette Score', fontweight='bold')
ax2.set_title('Silhouette Score by K', fontweight='bold')
ax2.grid(True, alpha=0.3)
ax2.axvline(x=3, color='red', linestyle='--', alpha=0.5, label='Peak at K=3')
ax2.legend()

plt.tight_layout()
plt.show()

The elbow occurs at K=3 (inertia stops dropping dramatically), and silhouette score peaks at K=3. This confirms 3 is a good choice for this data.

Dimension Reduction with PCA

The Problem: Too Many Features

Modern datasets are getting wider and wider—hundreds or thousands of features:

Challenges of high dimensionality:

  • Curse of dimensionality: Data becomes sparse in high-D space
  • Computational cost: Training takes forever
  • Overfitting risk: More features = more noise
  • Multicollinearity: Correlated features confuse models
  • Visualization: Can’t plot 100 dimensions!

Examples:

  • Healthcare: 20,000+ genes measured per patient
  • Computer vision: Images with millions of pixels
  • E-commerce: 500+ features per customer
  • Text analysis: Thousands of word counts per document

Question: Do we really need ALL these features?

The good news: often 10-20 carefully constructed features capture 90%+ of the information in 100 original features.

Main Takeaway: Recognize the problems caused by having too many features and understand the trade-offs of dimension reduction.

Question Analysis:

1. Which problems suggest you have too many features?

  • Correlated features: Yes! Multicollinearity causes unstable models
    • If sq ft and bedrooms are correlated, they provide redundant information
    • Models can’t distinguish their individual effects
    • Feature weights become unreliable
  • Long training time (30 minutes): Yes! More features = more computation
    • 100 features vs. 10 features = 10× more parameters to estimate
    • Exponentially slower for some algorithms
  • Test accuracy worse than training: Yes! Classic sign of overfitting
    • With 100 features and limited data, model memorizes noise
    • High-dimensional spaces are sparse (curse of dimensionality)
    • Model can’t generalize to new data

2. What might you gain by reducing from 100 to 10 features?

  • Faster training: 10-100× speedup depending on algorithm
  • Better generalization: Less overfitting, better test performance
  • Simpler models: Easier to understand, explain, and deploy
  • Visualization: Can actually plot and explore the data
  • Less multicollinearity: Components are uncorrelated by design
  • Noise reduction: Minor components often represent measurement noise

3. What might you lose?

  • Some information: PCA with 10 components might capture 90% of variance, but you lose 10%
  • Interpretability: Original features (“sq ft”) are intuitive; PC1 is a weighted combination that’s harder to explain
  • Specific details: Rare patterns captured by minor components are lost
  • Reversibility: You can’t perfectly reconstruct the original 100 features from 10 components

Key Teaching Insight: “PCA is always a trade-off. You’re betting that the information you LOSE (10-20% of variance, usually noise) is worth the benefits you GAIN (speed, simplicity, generalization). In practice, this trade-off is almost always favorable for high-dimensional data.”

What is Dimension Reduction?

Dimension reduction transforms your data from high-dimensional space to lower-dimensional space while preserving most of the important information.

Two main approaches:

  • Feature Selection: Pick a subset of original features (e.g., select the 10 most important)
  • Feature Extraction: Create NEW features by combining originals (e.g., PCA creates “principal components”)

Important

Today we focus on PCA (Principal Component Analysis) — the most widely-used feature extraction method.

Think of PCA like image compression: a 10MB photo can compress to 500KB while still looking nearly identical. PCA does the same for tabular data.

Principal Component Analysis (PCA): Visual Overview

How PCA transforms many correlated features into fewer uncorrelated components:

This diagram shows how PCA takes 50 correlated features and creates new uncorrelated components, with the first few capturing most of the variance.

PCA: The Intuition

PCA finds new coordinate axes (principal components) that capture maximum variance:

The idea:

  1. PC1 points in the direction where data varies the MOST
  2. PC2 points in the next-most variation direction (perpendicular to PC1)
  3. PC3 points in the next direction (perpendicular to both)
  4. And so on…

Key Insight

Often the first 5-10 components capture 90%+ of the total variation! This means you can reduce from 50 features to just 5-10 components while retaining most of the information.

Analogy: Imagine taking photos at a concert. One angle (PC1) captures most of the action. Adding a second angle (PC2) adds some new perspective. A third angle (PC3) adds a bit more. After that, additional angles don’t reveal much new information.

Interpreting the Principal Components:

PC1 (Red arrow - ~80-85% of variance):

  • Points in the direction where houses vary the MOST
  • Represents “Overall House Size” - a composite measure combining all three features
  • High PC1 score = large house with many bedrooms and bathrooms
  • Low PC1 score = small house with few bedrooms and bathrooms
  • This makes sense because sq ft, bedrooms, and bathrooms are all highly correlated - they increase together
  • Notice how PC1 points diagonally through the data cloud in the direction of maximum spread

PC2 (Teal arrow - ~10-15% of variance):

  • Perpendicular to PC1, captures the next-most variation
  • Might represent “Layout efficiency” or deviations from the typical size relationship
  • Example: A house with more bedrooms than expected for its square footage (positive PC2) vs. fewer bedrooms (negative PC2)
  • This captures residual variation NOT explained by overall size

PC3 (Blue arrow - ~5-10% of variance):

  • Perpendicular to both PC1 and PC2
  • Captures very small remaining variations
  • Might represent specific bathroom/bedroom trade-offs
  • Often this component is mostly noise and could be dropped

Teaching points:

  • Rotate the plot to show students how PC1 aligns with the “longest” dimension of the data cloud
  • Show how PC2 and PC3 are at right angles to PC1 (orthogonal/uncorrelated)
  • Emphasize that PC1 alone captures 80%+ of the variation, so we could reduce from 3 features to 1 component with minimal information loss
  • Ask: “If we only kept PC1, what information would we lose?” (Answer: The ability to distinguish houses with unusual bedroom/bathroom configurations for their size)

Step 3: How Many Components Should We Keep?

# Create scree plot
fig, (ax1, ax2) = plt.subplots(2, 1, figsize=(6, 6))

# Individual variance explained
variance_explained = pca_full.explained_variance_ratio_
ax1.plot(range(1, len(variance_explained) + 1),
         variance_explained, 'bo-', linewidth=2, markersize=8)
ax1.set_xlabel('Principal Component', fontweight='bold', fontsize=11)
ax1.set_ylabel('Variance Explained', fontweight='bold', fontsize=11)
ax1.set_title('Scree Plot: Variance per Component', fontweight='bold', fontsize=12)
ax1.grid(True, alpha=0.3)
ax1.axvline(x=7, color='red', linestyle='--', alpha=0.7, label='Elbow around PC7')
ax1.legend()

# Cumulative variance explained
cumsum = np.cumsum(variance_explained)
ax2.plot(range(1, len(cumsum) + 1), cumsum, 'ro-', linewidth=2, markersize=8)
ax2.axhline(y=0.95, color='green', linestyle='--', linewidth=2, label='95% threshold')
ax2.axhline(y=0.90, color='orange', linestyle='--', linewidth=2, label='90% threshold')
ax2.set_xlabel('Number of Components', fontweight='bold', fontsize=11)
ax2.set_ylabel('Cumulative Variance', fontweight='bold', fontsize=11)
ax2.set_title('Cumulative Variance Explained', fontweight='bold', fontsize=12)
ax2.legend()
ax2.grid(True, alpha=0.3)

# Find components needed for 95%
n_95 = np.argmax(cumsum >= 0.95) + 1

Then we’ll take a few responses…

Main Takeaway: Practice reading scree plots and making informed decisions about how many components to retain.

Question Analysis:

1. How many components would you keep? Why?

Let’s calculate cumulative variance for each option:

  • PC1 only: 35% variance — Too little information!
  • PC1-2: 35% + 20% = 55% variance — Still losing half the information
  • PC1-3: 55% + 12% = 67% variance — Getting better, but below typical threshold
  • PC1-4: 67% + 8% = 75% variance — Good threshold, retained 3/4 of information
  • PC1-5: 75% + 6% = 81% variance — Even better, common threshold
  • PC1-6+: 81% + 19% = 100% variance — Keeping 45 components for last 19%? Diminishing returns!

Recommended answer: Keep PC1-5 (81% variance)

  • Common rule of thumb: Aim for 80-90% cumulative variance
  • PC1-4 (75%): Also defensible if simplicity is paramount
  • PC1-10: Might be justified if you really need that extra precision

2. If you keep just PC1 and PC2, what percentage do you retain?

  • Answer: 35% + 20% = 55% of variance
  • Is this enough?
    • For visualization: Yes! Often we reduce to 2-3 components just to plot
    • For modeling: Probably not—you’re losing 45% of information
    • For exploration: Maybe—depends if those 2 components capture the main patterns

3. What are you trading off when you reduce from 50 to 5 features?

  • Gain: 90% reduction in features (50 → 5)
  • Lose: 19% of variance (81% retained, 19% lost)
  • The trade-off:
    • That 19% you’re losing is spread across 45 components (PC6-50)
    • Each of those captures < 0.5% of variance on average
    • Likely represents noise, measurement error, or very subtle patterns
    • The first 5 components capture the “signal,” the rest is mostly “noise”

Key Teaching Points:

  • “There’s no universal ‘right’ answer—it depends on your goals”
  • “For modeling: usually keep components up to 80-90% variance”
  • “For visualization: often just keep 2-3 components”
  • “Look for the ‘elbow’ in scree plot—where adding more components gives diminishing returns”
  • “In this example, PC6+ each add < 1% variance—probably not worth the complexity”

Real-World Context: “Imagine you’re building a recommendation system. You might reduce 10,000 product features to 50 components (99% variance) for speed, or reduce to 10 components (95% variance) if you need real-time predictions. The choice depends on your business requirements!”

Main Takeaway: Principal components are interpretable by examining which original features contribute most strongly (highest loadings).

What are “loadings”?

  • Loadings = weights that show how much each original feature contributes to a principal component
  • High absolute loading = that feature strongly influences this component
  • Positive loading = feature increases with the component
  • Negative loading = feature decreases with the component
  • Near-zero loading = feature doesn’t contribute much to this component

How to Interpret PC1 in Breast Cancer Data:

Looking at the top features from the code output, we’ll see:

  1. radius_worst (high loading): Largest radius measurement
  2. perimeter_worst (high loading): Largest perimeter
  3. area_worst (high loading): Largest area
  4. concave points_worst (high loading): Most severe concavity
  5. radius_mean (high loading): Average radius
  6. perimeter_mean (high loading): Average perimeter

What does this tell us?

  • PC1 is dominated by SIZE and IRREGULARITY measurements
  • All the “worst” measurements (most extreme values) load heavily
  • Interpretation: PC1 represents “Overall Tumor Severity”
    • High PC1 score → Large tumor with irregular features → Likely malignant
    • Low PC1 score → Small tumor with regular features → Likely benign

Teaching Strategy:

  1. Show the loadings table from the code output
  2. Ask: “What do these top features have in common?” → All relate to size/shape
  3. Explain: “PC1 is a weighted average of these features—a single score summarizing tumor severity”
  4. Contrast with original features: “Instead of looking at 30 separate measurements, PC1 gives you ONE number that captures the most important pattern”

Why This Matters:

  • PCA creates new features, but they’re NOT random or meaningless
  • Each component has an interpretation based on its loadings
  • Good practice: Always examine loadings to understand what your components represent
  • You can name components based on their interpretation (e.g., “Tumor Severity Score”)

Common Student Question: “Are all loadings equally important?” → No! Focus on the highest absolute loadings—those features dominate that component. Small loadings (< 0.1) contribute very little.

PCA as Feature Engineering for Machine Learning

Another powerful use case: Use PCA-transformed features as input to ML models

Why use PCA before modeling?

  • Reduces overfitting - Fewer features = simpler model = better generalization
  • Speeds up training - Fewer features = faster computation
  • Handles multicollinearity - PCs are uncorrelated by design
  • Removes noise - Minor components often represent noise

Let’s compare model performance with and without PCA using our breast cancer data:

Emphasize that PCA is often used as a preprocessing step in ML pipelines, not just for visualization. This is a key practical application that students will use in real projects.

Why Accept Slightly Lower Accuracy?

Even if PCA features have slightly lower accuracy, the tradeoffs are often worth it:

Benefits of Using PCA:

  1. Faster training & prediction
    • 7 features vs. 30 = ~4× speedup
    • Matters for large datasets or complex models
  2. Reduced overfitting risk
    • Simpler model = less prone to memorizing noise
    • Better generalization to new data
  3. Eliminates multicollinearity
    • PCs are uncorrelated by design
    • Helps algorithms that assume independence

More Benefits:

  1. Easier deployment
    • Smaller models are faster to deploy
    • Require less memory in production
  2. Noise filtering
    • Discarding minor components removes noise
    • Can actually improve performance!
  3. Scalability
    • With 100s-1000s of features, PCA becomes essential
    • Our 77% reduction would be even more dramatic

The Key Tradeoff

PCA trades a small amount of accuracy for significant gains in speed, simplicity, and robustness. As datasets grow larger and wider, this tradeoff becomes increasingly favorable.

Using Clustering/PCA in ML Pipelines

Unsupervised methods often feed into supervised models:

Example workflow:

  1. Reduce 100 features to 20 components with PCA (noise reduction)
  2. Cluster customers into 5 segments using K-Means on those 20 components
  3. Add cluster ID as a categorical feature
  4. Train a Random Forest to predict customer churn using PCA components + cluster ID

Benefit: Unsupervised learning creates better features for supervised learning!

This is a very common pattern in practice. Clustering and dimension reduction as preprocessing steps for prediction models. Emphasize that PCA and clustering aren’t just standalone techniques—they’re often combined and used to engineer features for supervised learning.

Key Takeaways & Next Steps

Key Takeaways

  • Unsupervised learning discovers patterns without labels – Use it when you want to explore data structure rather than predict outcomes

  • Clustering groups similar observations – K-Means is the workhorse for customer segmentation, but choosing K requires judgment (elbow method, silhouette scores, business constraints)

  • PCA reduces dimensionality by creating uncorrelated components – Compress 100 features to 10 components while retaining 90%+ of information. Use scree plots to choose how many components to keep.

  • ALWAYS standardize features first – Both K-Means and PCA are highly sensitive to feature scale. Forget this and your results will be dominated by large-scale features!

  • Unsupervised → Supervised pipeline – Often you’ll use clustering/PCA as preprocessing steps to create better features for supervised learning models

These are the core concepts. Emphasize that unsupervised learning is about exploration and feature engineering, not prediction accuracy.

When to Use Which Method

    • Feature engineering before supervised learning
    • Data visualization (reduce to 2-3 components for plotting)
    • Noise reduction (keep components, discard noise)
    • Compression for faster computation

Goal 3: Both! (Use PCA then Clustering)

  • When to use:

    • “I have many correlated features AND want to find segments”
    • “Clustering on 100 features is computationally expensive”
    • “I want to remove noise before clustering”

  • Workflow:

    1. Apply PCA to reduce 100 features → 20 components (faster, less noisy)
    2. Apply K-Means to those 20 components (find customer segments)
    3. Use segments as features for supervised learning (predict churn for each segment)

  • Example use cases:

    • Customer segmentation with behavioral + demographic data
    • Image clustering (reduce pixel features with PCA, then cluster)
    • Gene expression analysis (reduce 20,000 genes → 50 components → cluster patients)

Decision-Making Questions:

  1. “What’s your PRIMARY goal?”
    • Discover groups → Clustering
    • Simplify features → PCA
    • Both → PCA first, then Clustering
  2. “Do you have too many features?”
    • Yes → Consider PCA first
    • No → Go straight to clustering if you want groups
  3. “Are your features highly correlated?”
    • Yes → PCA will help a lot
    • No → Maybe feature selection instead of PCA

Real-World Insight: “In practice, the combo approach (PCA → Clustering → Supervised Learning) is very common. It’s like a data science pipeline: reduce complexity, discover patterns, then predict outcomes.”
